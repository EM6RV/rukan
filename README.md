# رُكن — RUKN

> ركنك في السوق… أونلاين.

منصة SaaS متعددة المتاجر للبياعين في ليبيا: أي بياع (إنستغرام، تيك توك، محل) يسجّل في دقيقتين ويطلع عنده متجر إلكتروني جاهز ولوحة تحكم كاملة، مقابل اشتراك شهري. المواصفات الكاملة في [`CLAUDE.md`](./CLAUDE.md).

**التقنيات:** Next.js (App Router) + TypeScript + Tailwind · Turso (libSQL) + Drizzle · جلسات httpOnly + argon2 · تخزين صور قابل للتبديل (Turso / Cloudflare R2) · الاستضافة على Render.

## 1) التشغيل المحلي

المطلوب: Node.js 22 وpnpm 10 (`corepack enable`).

```bash
pnpm install
cp .env.example .env            # عدّل ADMIN_PHONE و ADMIN_PASSWORD
pnpm db:setup                   # migrations + الباقات + مدن ليبيا + حساب الأدمن
pnpm db:seed:demo               # (اختياري) 3 متاجر تجريبية بمنتجات وطلبيات وموظفين
pnpm dev
```

| الرابط | الوصف |
|---|---|
| <http://localhost:3000> | موقع رُكن التسويقي |
| `/dashboard` | لوحة البياع |
| `/admin` | لوحة الأدمن (حساب `ADMIN_PHONE`) |
| `/s/nada-perfume` · `/s/street-218` · `/s/lamsa` | المتاجر التجريبية الثلاثة (أنيق، جريء، بسيط). بدلها `http://nada-perfume.localhost:3000` يشتغل كساب دومين |
| `/api/health` | فحص الصحة (`?db=1` يفحص القاعدة كمان) |

حسابات `db:seed:demo`: البياع `0910000011` (عطور الندى) و`0910000012` و`0910000013`، وموظف طلبيات `0920000011`، ومندوب `0930000011` — كلها بكلمة السر `demo-password-123`. **للتطوير فقط، لا تشغّل seed-demo في الإنتاج.**

## 2) الميزات

- **الأساس:** عزل بيانات المتاجر (composite FKs + `forStore`)، مصادقة آمنة، RTL عربي ونظام تصميم.
- **البياع:** تسجيل ومعالج إعداد، منتجات بمتغيرات ومخزون وصور، استيراد Excel/CSV، أقسام، إعدادات.
- **واجهة المتجر:** 6 قوالب (نقاء، مخمل، نبض، سوق، حكاية، لمسة) مع فلترة وبحث بالاقتراحات والمفضلة وتقييمات المشترين الموثّقين، سلة، إتمام طلب بدون حساب، دفع عند الاستلام أو تحويل بإيصال، كوبونات، تتبع الطلبية، SEO وPixels.
- **المندوبين والكاش اختياري:** من الإعدادات ← التوصيل يقدر البياع يقفل «أستعمل مندوبين» (افتراضياً شغّال). المقفل يخفي صفحة المندوبين وفلوسك عند المندوبين وتسليم الطلبية لمندوب، وتسلّم الطلبيات مباشرة (تأكيد ← تم التوصيل). ما يمسح بيانات قديمة.
- **التشغيل:** طلبيات بحالات وتأثيرات تلقائية، مندوبون وكاش وتسويات، مرتجعات، زبائن، توصيل لكل مدينة، واتساب برسائل جاهزة، تنبيه الطلبيات الجديدة.
- **التخصيص والتسويق:** تعديل كل محتوى المتجر مع معاينة، قالب/ألوان/خط، كوبونات، Pixels، تقارير مع تصدير Excel، موظفون بصلاحيات.
- **التشغيل المتقدم:** إشعارات Web Push للطلبية الجديدة وللمندوب عند التعيين، سلات متروكة مع تذكير واتساب، صفحة مندوب للجوال (قابلة للتثبيت PWA)، استرجاع كلمة السر عبر واتساب بوساطة الأدمن.
- **خدمات التصميم:** صفحة في لوحة البياع لطلب ريل/لوجو/هوية (السعر حسب الطلب، والتفاصيل على واتساب الدعم)، والباقة السنوية فيها تصميم مجاني لكل فترة اشتراك. الأدمن يشوف الطلبات في «طلبات التصميم». لازم تحدد «واتساب الدعم» من إعدادات الأدمن.
- **الكتالوج المتقدم:** براندات ووسوم، مكتبة خيارات جاهزة، باقات منتجات (مخزونها يتحسب من مكوناتها)، تخصيص المنتج (اسم/نقش بسعر إضافي)، تواريخ صلاحية، تعديل جماعي في جدول، حركات المخزون وتنبيه المخزون القليل (حسب الباقة).
- **الوحدات الاختيارية (من صفحة الوحدات، حسب الباقة):** المخازن (تحويلات وجرد)، المشتريات (موردين وفواتير وتكلفة متوسطة مرجّحة)، الحسابات (دفتر أستاذ لا يُعدَّل، مصاريف، ديون الزباين، إقفال الصندوق، أرباح وخسائر). الأخطاء تُصحَّح بقيد عكسي مش بالتعديل.
- **المبيعات والتشغيل:** طلبية يدوية، أدوار مخصصة بصلاحيات، تحليلات الزيارات والتحويل، سجل نشاط المتجر، طباعة بوليصة حرارية، شركات توصيل وروابط تتبع، سلات متروكة مع رابط استرجاع. **محولات الدفع والتوصيل (adapters) ومحادثات الماركت والرسائل مجرّد هيكل مطفي بالتصميم**: ما فيه ربط حقيقي بأي بوابة لين تحددها وتعطي مفاتيحها.
- **الموقع التسويقي:** صفحات القطاعات `/for/[slug]` والقوالب `/templates/[key]` و`sitemap.xml` و`robots.txt`، وكل النصوص تتعدل من لوحة الأدمن ← محتوى الموقع.
- **الأدمن:** المتاجر، الاشتراكات والدفعات اليدوية (تجديد تلقائي)، الباقات، الإعلانات، سجل النشاط، محتوى الموقع التسويقي، إعدادات المنصة.
- **الباقات والحدود:** ثلاث باقات، لكل وحدة مدة وحدة وسعر واحد: شهرية (250 د.ل، نص المزايا) / ست شهور (650 د.ل) / سنوية (1250 د.ل، فل مزايا)، قابلة للتعديل من الأدمن، والحدود تتفرض فعلياً في الكود.

## 3) النشر على Render خطوة بخطوة

### المتطلبات
- حساب GitHub، حساب [Render](https://render.com)، حساب [Turso](https://turso.tech)، ودومين (مثل `rukn.ly`) تقدر تعدّل DNS تبعه.
- (اختياري) حساب Cloudflare لو تبي صور على R2.

### الخطوة 1 — قاعدة البيانات (Turso)
```bash
curl -sSfL https://get.tur.so/install.sh | bash     # أو brew install tursodatabase/tap/turso
turso auth login
turso db create rukn --location fra                  # أقرب منطقة لليبيا
turso db show rukn --url                             # → DATABASE_URL  (libsql://rukn-اسمك.turso.io)
turso db tokens create rukn                          # → DATABASE_AUTH_TOKEN
```
> **لا تستعمل قاعدة ملف على Render**: قرص الخدمة يتمسح مع كل نشر. التطبيق يرفض التشغيل في الإنتاج بقاعدة `file:` (إلا لو حطيت `ALLOW_LOCAL_DB=1` وعندك قرص دائم).

### الخطوة 2 — (اختياري) صور على Cloudflare R2
1. Cloudflare ← R2 ← أنشئ bucket (مثلاً `rukn-media`).
2. R2 ← Manage API Tokens ← أنشئ token بصلاحية Object Read & Write على الـ bucket.
3. احفظ: `R2_ACCOUNT_ID` و`R2_ACCESS_KEY_ID` و`R2_SECRET_ACCESS_KEY` و`R2_BUCKET`، وحط `STORAGE_DRIVER=r2`.

الصور تتقدّم عبر `/api/media` (التطبيق يقراها من R2 ويكاشها بالمتصفح)، فما تحتاج تفتح الـ bucket للعموم. لو بدأت بـ `turso` وبغيت تنتقل لاحقاً، الصور القديمة تبقى في Turso والجديدة تروح R2 (كل صورة تعرف مكان تخزينها).

### الخطوة 3 — الكود على GitHub
```bash
git remote add origin git@github.com:<حسابك>/rukn.git
git push -u origin main
```

### الخطوة 4 — Render
1. Render ← **New** ← **Blueprint** ← اختر المستودع. يقرا `render.yaml` وينشئ Web Service اسمه `rukn`.
2. عبّي المتغيرات اللي `sync: false` (القاعدة، الأدمن، R2 لو تستعمله) — الجدول في [القسم 4](#4-متغيرات-البيئة).
3. **Deploy.** أمر البناء: `corepack enable && pnpm install --frozen-lockfile --prod=false && pnpm build`. أمر التشغيل `pnpm start:prod` يطبّق الـ migrations ويضيف الباقات والمدن (idempotent، آمن يتكرر) ثم يشغّل التطبيق.
4. تأكد: `https://<خدمتك>.onrender.com/api/health?db=1` ترجع `{"ok":true,"db":"up"}`.

> **الخطة المجانية** تنام بعد 15 دقيقة خمول (أول طلب بعدها بطيء). للإنتاج استعمل **Starter** على الأقل. لو بتبقى على المجانية: برنامج keep-alive (مثل cron-job.org) يضرب `https://rukn.ly/api/health` كل 10 دقايق.

### الخطوة 5 — فحص الإعدادات قبل الإطلاق (اختياري لكن مفيد)
```bash
NODE_ENV=production STRICT_PRODUCTION=1 pnpm check:env
```
على Render يتفحص تلقائياً عند كل تشغيل (`RENDER=true`): أي إعداد خطير (APP_URL بدون https، ROOT_DOMAIN محلي، قاعدة ملف، توكن ناقص) يوقف التشغيل برسالة واضحة.

## 4) متغيرات البيئة

| المتغير | مطلوب؟ | الوصف |
|---|---|---|
| `NODE_ENV` | نعم | `production` |
| `APP_URL` | نعم | رابط التطبيق الأساسي بـ https، مثل `https://rukn.ly` |
| `ROOT_DOMAIN` | نعم | الدومين الرئيسي بدون https ولا منفذ، مثل `rukn.ly`. المتاجر تكون `slug.rukn.ly` |
| `DATABASE_URL` | نعم | `libsql://…turso.io` |
| `DATABASE_AUTH_TOKEN` | نعم | توكن Turso |
| `STORAGE_DRIVER` | لا | `turso` (افتراضي) أو `r2` |
| `R2_ACCOUNT_ID` · `R2_ACCESS_KEY_ID` · `R2_SECRET_ACCESS_KEY` · `R2_BUCKET` | مع r2 | بيانات Cloudflare R2 |
| `ADMIN_NAME` · `ADMIN_PHONE` · `ADMIN_PASSWORD` | أول مرة | حساب الأدمن، يُنشأ لو غير موجود. كلمة السر ≥ 12 حرف وغير افتراضية. **احذف `ADMIN_PASSWORD` بعد أول تشغيل** |
| `TRUSTED_PROXY_HOPS` | لا | عدد البروكسيات قدام التطبيق (Render = `1`) — لقراءة IP العميل بأمان وحدود المحاولات |
| `TRUST_CLOUDFLARE` | لا | `1` لو Cloudflare قدام Render |
| `CUSTOM_DOMAIN_TARGET` | لا | هدف CNAME للدومينات الخاصة، مثل `rukn.onrender.com`. الافتراضي `cname.ROOT_DOMAIN` |
| `ALLOW_LOCAL_DB` | لا | `1` يسمح بقاعدة ملف في الإنتاج (فقط مع قرص دائم) |
| `VAPID_PUBLIC_KEY` · `VAPID_PRIVATE_KEY` · `VAPID_SUBJECT` | لا | إشعارات الطلبيات (Web Push). ولّد المفاتيح بـ `pnpm push:keys`. بدونها الإشعارات تتعطل بهدوء |

## 5) الدومين والـ wildcard

المنصة تعتمد على النطاقات: `rukn.ly` (الموقع + اللوحات) و`*.rukn.ly` (المتاجر). الـ proxy داخل التطبيق يقرا الـ Host ويوجّه.

### سجلات DNS (عند مزوّد الدومين أو Cloudflare)
| النوع | الاسم | القيمة |
|---|---|---|
| CNAME (أو ALIAS/A للجذر) | `rukn.ly` (`@`) | `<خدمتك>.onrender.com` |
| CNAME | `www` | `<خدمتك>.onrender.com` |
| CNAME | `*` | `<خدمتك>.onrender.com` |

### في Render
خدمتك ← **Settings** ← **Custom Domains** ← أضف:
- `rukn.ly`
- `www.rukn.ly`
- `*.rukn.ly` (wildcard)

Render يتحقق من DNS ويصدر شهادات TLS تلقائياً. (دعم الـ wildcard وشروطه يتغير؛ راجع توثيق Render الحالي «Custom Domains / Wildcard» لو واجهت مشكلة في التحقق.)

### لو تستعمل Cloudflare
- خلّي SSL/TLS على **Full (strict)**.
- فعّل `TRUST_CLOUDFLARE=1` وخلّي `TRUSTED_PROXY_HOPS=2` (Cloudflare ثم Render) أو اعتمد `cf-connecting-ip`.
- سجل `*` يقدر يكون Proxied (سحابة برتقالية) أو DNS only؛ مع Proxied تأكد من SSL/TLS = Full (strict) وإن Render أصدر شهادة للدومين.

### للتجربة بدون دومين
افتح `https://<خدمتك>.onrender.com` (يعامل كموقع المنصة). المتاجر على `/s/<slug>`.

## 6) الدومين الخاص للبياعين

ميزة الباقة السنوية. الخطوات:

1. **البياع:** الإعدادات ← تبويب «الدومين» ← يكتب دومينه (مثل `shop.example.com`).
2. التطبيق يعرض له سجلين يضيفهم في DNS دومينه:
   - **TXT** باسم `_rukn-verify.shop.example.com` بقيمة `rukn-verify=<توكن خاص بمتجره>` (إثبات الملكية — يمنع أي متجر ثاني من خطف دومين غيره).
   - **CNAME** من `shop.example.com` إلى `CUSTOM_DOMAIN_TARGET` (أو `cname.rukn.ly`). للدومين الجذر بدون CNAME يستعمل A لنفس عناوين الهدف.
3. البياع يضغط «تحقق الآن». لازم الاثنين يتحققوا.
4. **أنت (الأدمن):** أضف نفس الدومين في Render ← Custom Domains علشان يتجهز له شهادة TLS ويوصل الطلب للتطبيق. (Render ما عنده API لهذي الخطوة في هذا الإعداد، فهي يدوية.)
5. لو DNS ما يتحقق آلياً (مزوّد غريب)، من لوحة الأدمن ← المتجر ← «اعتماد يدوي».

لو نزلت باقة المتجر، الدومين الخاص يوقف تلقائياً والمتجر يبقى على `slug.rukn.ly`.

## 7) أول تشغيل بعد النشر

1. ادخل `https://rukn.ly/login` بحساب الأدمن ← `/admin`.
2. **الإعدادات:** حط **واتساب الدعم** (يظهر للبياعين عند التجديد وفي فوتر الموقع)، وراجع أيام التجربة وباقة التجربة.
3. **الباقات:** راجع الأسعار والحدود (الافتراضي: شهرية 250 / ست شهور 650 / سنوية 1250 د.ل).
4. **موقع رُكن:** عدّل نصوص الصفحة الرئيسية وصورها.
5. احذف `ADMIN_PASSWORD` من متغيرات Render (الأدمن اتنشأ، وما عاد له لزوم).
6. جرّب تسجيل بياع تجريبي من نافذة خاصة، أكمل المعالج، واطلب من متجره طلبية.
7. **تسجيل دفعة:** الأدمن ← المتاجر ← المتجر ← «تسجيل دفعة» (المبلغ، كاش/تحويل، إيصال) ← الاشتراك يتفعل ويتجدد تلقائياً.
8. **نسي البياع كلمة السر:** يضغط «نسيت كلمة السر؟» في صفحة الدخول فيوصلك طلب في الأدمن ← «طلبات كلمة السر». تتأكد من هويته (يكلمك من نفس الرقم على واتساب) وتضغط «جهّز الرابط» ثم «ابعثه على واتساب». الرابط صالح ساعة ولمرة وحدة. (البديل اليدوي: الأدمن ← المتجر ← «كلمة سر المالك».)
9. **إشعارات الطلبيات (اختياري):** شغّل `pnpm push:keys` وحط القيم الثلاث (`VAPID_*`) في Render ثم أعد النشر. بعدها تظهر في رئيسية اللوحة بطاقة «فعّل إشعارات الطلبيات»، والمندوب يشوفها في صفحة طلبياته. على آيفون الإشعارات تشتغل بعد «إضافة إلى الشاشة الرئيسية».
10. **إبقاء الموقع صاحي (الخطة المجانية):** Render المجاني ينام بعد 15 دقيقة خمول. اضرب `https://<خدمتك>.onrender.com/api/health` كل 5 دقايق من UptimeRobot أو cron-job.org. لا تستعمل `?db=1` في الـ keep-alive.

## 8) النسخ الاحتياطي والاستعادة

**قاعدة البيانات (Turso):**
```bash
turso db shell rukn .dump > backup-$(date +%F).sql          # نسخة كاملة
turso db create rukn-restore --from-dump backup-2026-01-01.sql   # استعادة لقاعدة جديدة
turso db create rukn-pitr --from-db rukn --timestamp 2026-01-01T10:00:00Z   # استعادة لنقطة زمنية (حسب خطتك)
```
خذ نسخة دورية (cron خارجي أو GitHub Action) واحفظها خارج Render. لو بدلت قاعدة، غيّر `DATABASE_URL`/`DATABASE_AUTH_TOKEN` وأعد النشر.

**الصور:** مع `turso` هي داخل القاعدة (تدخل في النسخة الاحتياطية). مع `r2` فعّل Object Versioning أو انسخ الـ bucket دورياً (`rclone sync`).

## 9) التحديثات والـ migrations

1. عدّل `src/db/schema/*` ثم `pnpm db:generate` وارفع ملفات `src/db/migrations` مع الكود.
2. كل نشر على Render يشغّل `pnpm db:migrate` تلقائياً قبل التطبيق (في `start:prod`)، وهو آمن لو ما فيه جديد.
3. **التغييرات المدمّرة** (حذف أعمدة/جداول): اعملها على مرحلتين (أول نشر يوقف استعمالها، ثاني نشر يحذفها) وخذ نسخة احتياطية قبلها.
4. migrations الإصدار الثاني: `0011` تحويل القوالب القديمة للجديدة (بيانات)، `0012` كتالوج وتقييمات، `0013` أدوار وتحليلات وسلات، `0014` مخازن ومشتريات، `0015` دفتر الأستاذ (فيه triggers تمنع التعديل والحذف)، `0016` صندوق الرسائل. تتطبق بالترتيب تلقائياً وتشتغل على قاعدة جديدة وقديمة.
5. التراجع عن نسخة تطبيق: Render ← Deploys ← Rollback. الـ migrations ما تتراجع تلقائياً، فاكتبها متوافقة للخلف (إضافة أعمدة بقيم افتراضية).

## 10) الأمان

مطبّق في الكود:
- **عزل المتاجر:** كل استعلام عبر `forStore(storeId)` + مفاتيح أجنبية مركّبة `(store_id, id)` تمنع الربط بين متجرين حتى لو غلط الكود، واختبارات تفحص كل الجداول.
- **المصادقة:** argon2، جلسات httpOnly + `__Host-` وSameSite=Lax، توكن الجلسة يُخزَّن مجزّأً، rate limit على الدخول والتسجيل والطلبيات والتتبع والكوبونات.
- **الصلاحيات:** مصفوفة أدوار (مالك/مدير/موظف طلبيات/مندوب) تتفرض في السيرفر، والمندوب يشوف طلبياته فقط. **حارس آلي** (`tests/guards.test.ts`) يفشل لو أي server action أو API route جديد بدون تحقق صلاحية أو فحص CSRF.
- **الترويسات (إنتاج):** CSP، HSTS، `X-Frame-Options`، `nosniff`، `Referrer-Policy`، `Permissions-Policy`.
- **المدخلات:** Zod لكل مدخل، تهريب LIKE، روابط البانرات https/داخلية فقط، معرّفات Pixel بصيغة صارمة، نصوص المتاجر تُعرض كنص عادي (لا HTML)، JSON-LD مهرّب.
- **الصور:** تتحقق من المحتوى الفعلي، تُحوَّل WebP بدون metadata، ولا تقبل SVG. الإيصالات خاصة (للمتجر والأدمن فقط).
- **التصدير:** حماية من حقن الصيغ في CSV.
- **IP العميل:** يُقرأ من يمين `X-Forwarded-For` (لا يمكن تزويره من العميل) حسب `TRUSTED_PROXY_HOPS`.
- **الإنتاج:** يرفض التشغيل بإعداد غير آمن، والأدمن لازم كلمة سر قوية، وسجل نشاط (audit) للعمليات الحساسة.
- **التبعيات:** `pnpm audit --prod` نظيف وقت التسليم؛ شغّله دورياً.

قائمة فحص قبل الإطلاق:
- [ ] `pnpm check:env` يمر، `/api/health?db=1` يرجع up.
- [ ] `ADMIN_PASSWORD` اتحذفت من Render بعد إنشاء الأدمن.
- [ ] الدومين وwildcard وTLS شغالين، وشفرة المتجر `https://slug.rukn.ly` تفتح.
- [ ] جرّبت: تسجيل بياع ← متجر ← طلبية ← تأكيد ← تسجيل دفعة.
- [ ] واتساب الدعم مضبوط، والنسخ الاحتياطي لـ Turso مجدول.
- [ ] `pnpm audit --prod` و`pnpm test` و`pnpm lint` نظيفين على آخر commit.

## 11) حل المشاكل الشائعة

| العرض | السبب والحل |
|---|---|
| الخدمة ما تقوم: «إعدادات الإنتاج غير آمنة» | اقرا الرسالة: غالباً `APP_URL` بدون https أو `ROOT_DOMAIN` فيه منفذ أو `DATABASE_URL` ملف |
| `DATABASE_AUTH_TOKEN مطلوب` | حط توكن Turso (`turso db tokens create rukn`) |
| فشل البناء: `tailwindcss`/`typescript` غير موجود | أمر البناء لازم `pnpm install --prod=false` (موجود في `render.yaml`) |
| `slug.rukn.ly` يرجع موقع المنصة أو خطأ شهادة | سجل `*` أو الـ wildcard في Render Custom Domains ناقص |
| كل الزباين «محاولات كثيرة» | `TRUSTED_PROXY_HOPS` غلط فكل الطلبات تظهر بنفس IP. مع Cloudflare: `TRUST_CLOUDFLARE=1` |

| تعديل من الأدمن ما ظهر في المتجر | الكاش يتفرغ تلقائياً؛ لو بقي، حدّث الصفحة (الكاش 2 إلى 5 دقايق كحد أقصى لغير التعديلات المباشرة) |

## 13) هيكلة الكود وقاعدة العزل

```
src/app/            الصفحات: (auth) · onboarding · dashboard · admin · s/[key] (المتاجر) · print · api
src/server/         المنطق: tenant/ (forStore) · orders/ · catalog/ · admin/ · auth/ · storage/ · storefront/
src/db/schema/      platform.ts (مستخدمون، متاجر، باقات…) و tenant.ts (كل جداول المتجر + store_id)
src/lib/            أدوات مشتركة محايدة (مال، هاتف، مدن، فوترة، CSP، IP…)
src/components/     ui/ · dashboard/ · store/ (القوالب) · marketing/ · admin/
tests/              اختبارات vitest (قاعدة ملف مؤقتة لكل ملف)
```

بيانات أي متجر ما تتقرا ولا تتكتب إلا عبر `forStore(db, storeId)` من `src/server/tenant`. قاعدة ESLint تمنع استيراد جداول المتجر خارج هذه الطبقة، والاستثناء الوحيد قراءتان تجميعيتان للأدمن (`platformOrderTotals` و`platformStoreCounts`) أرقام فقط.

**كل الفلوس أعداد صحيحة بالدرهم** (1 د.ل = 1000)، والأرقام تُخزَّن بصيغة `09XXXXXXXX`، والتواريخ تُعرض بتوقيت ليبيا (UTC+2).

## 14) المنظومات: ماركت وبلاي وفِت

رُكن مش بس متجر أونلاين. كل بياع يقدر يشغّل منظومة أو أكثر من نفس الحساب، ولكل منظومة اشتراكها وباقاتها وحدودها (تتعدل من الأدمن).

### التفعيل
1. **الأدمن** (`/admin/settings`): كل منظومة لها حالة: `مخفية` / `تجريبية (beta)` / `شغّالة (live)`. حوّلها لـ **live** باش تظهر للبياعين في التسجيل.
2. **البياع:** يختار منظومته (أو أكثر) في التسجيل، ويكمل معالجاً قصيراً خاصاً بها (مثلاً: عدد الأجهزة وسعر الساعة للصالة، أنواع الاشتراك للنادي). الفترة التجريبية والباقات من `/admin/plans` (تبويب لكل منظومة).
3. تظهر قوائم المنظومة في اللوحة تحت «المنظومات»، وتتقفل الميزات خارج الباقة (القفل يتفرض في السيرفر مش بس في الواجهة).

### رُكن ماركت (بقالة/سوبرماركت)
- **الكاشير:** `/pos` على أي جهاز (موبايل/تابلت/كمبيوتر). يشتغل **بدون إنترنت** ويزامن لما ترجع الشبكة؛ العمليات تتحفظ في المتصفح وتتبعت تلقائياً، والسيرفر يعيد حساب الفواتير ويعلّم أي اختلاف «يحتاج مراجعة».
- **تركيبه كتطبيق على التابلت:** افتح `/pos` في Chrome ← القائمة ← «إضافة إلى الشاشة الرئيسية». أول مرة: من اللوحة `الفروع والأجهزة` أنشئ جهازاً وافتح رابط التفعيل عليه (رابط بتوكن، تقدر تلغيه).
- **قارئ الباركود:** أي قارئ USB/بلوتوث يشتغل كلوحة مفاتيح؛ يكفي يكون المؤشر على خانة البحث. أو كاميرا الموبايل (زر المسح).
- **الميزان:** إعدادات الميزان في `إعدادات الكاشير`. الأصناف الموزونة تُباع بالجرام والسعر للكيلو، وباركود الميزان (يبدأ بـ 2) يتفك تلقائياً. الاتصال المباشر بالميزان عبر Web Serial (Chrome فقط) تجريبي، **وما اتجرّبش على أجهزة حقيقية**.
- **الطابعة الحرارية:** 58 أو 80 مم من نافذة الطباعة العادية في المتصفح، أو ESC/POS عبر Web USB/Serial (تجريبي، ما اتجرّبش على أجهزة حقيقية).
- الدفعات وتواريخ الصلاحية (FEFO)، الإتلاف، العروض، اقتراح الشراء، الجرد بالكاميرا، دفتر الديون والمحافظ ونقاط الولاء، تقارير وتصدير Excel، وصفحة عامة `/market/اسم-المتجر`.

### رُكن بلاي (صالة ألعاب)
- **الأجهزة والأسعار:** `/dashboard/lounge/stations` و`/pricing` (سعر الساعة أو الماتش، لكل نوع جهاز/غرفة VIP/وقت، وباقات الساعات).
- **الكاشير:** نفس `/pos` على جهاز مفعّل بمنظومة الصالة؛ تبويب 🎮 الصالة فيه عدّاد لكل جهاز (بداية/إيقاف/نقل/إنهاء) ويشتغل بدون نت، وتبويب 🥤 البار للبيع العادي.
- **شاشة الحائط:** `/dashboard/lounge/tv` تعطيك رابطاً (يتحط في متصفح التلفزيون) يعرض حالة الأجهزة والبطولات. للعرض فقط.
- **الحجوزات والبطولات:** من اللوحة، والصفحة العامة `/play/اسم-المتجر` فيها طلب حجز (يستنى تأكيدك) وتسجيل بطولات، وكلها بحد للمحاولات.
- **التحكم بالكهرباء** (إطفاء الجهاز تلقائياً) و**بوابات الدخول**: واجهة (adapter) جاهزة لكنها «قريباً» وما فيها ربط حقيقي.

### رُكن فِت (نادي رياضي)
- **الأعضاء والاشتراكات:** `/dashboard/gym/members` (تسجيل، تجديد، تجميد، ترقية بالفرق، نقل، إلغاء باسترجاع، أقساط، عايلة). أنواع الاشتراك وساعات النساء ومهلة الأقساط في `/dashboard/gym/plans`.
- **الدخول:** `/dashboard/gym/reception` بالباركود (قارئ USB أو الكاميرا) أو برقم الهاتف، والبطاقة تُطبع من صفحة العضو. **الكشك** عند الباب: رابط بتوكن (من نفس صفحة الاستقبال) يعرض «أهلاً فلان — باقي 12 يوم» بدون أي بيانات حساسة.
- الحصص (حجز وقائمة انتظار)، المدربين وحصص PT والعمولات، رسائل واتساب جاهزة (`رسائل اليوم`: تجديد، قسط، غياب، ميلاد) تفتح واتساب بضغطة، وتقارير وتصدير Excel.
- **الصفحة الشخصية للعضو:** `/gym/اسم-المتجر/me` (هاتف + كلمة سر يحددها الاستقبال): الاشتراك والأقساط والبطاقة والحصص والبرنامج. الصفحة العامة للنادي `/gym/اسم-المتجر`.
- **بيع المكملات والمشروبات:** من `/pos` على جهاز بمنظومة النادي، على حساب العضو (يطلع زبوناً تلقائياً) أو كاش.
- **قياسات العضو وبرامجه وملاحظاته الصحية** بيانات حساسة: ما تظهر في أي رابط عام، وزر «مسح بيانات العضو» يحذفها بطلبه.
- **بوابات الدخول (Turnstile)** و**WhatsApp Business API** (إرسال تلقائي): adapters جاهزة لكنها «قريباً».

### الموقع التسويقي
قسم «رُكن مش بس متجر» وصفحة لكل منظومة `/systems/market|play|fit` وتبويب أسعار لكل منظومة، وكلها نصوصها من `/admin/site`.

### ما اتجرّب وما ما اتجرّبش
اتجرّب بالاختبارات الآلية وبالمتصفح (Chromium): كل الحسابات والخدمات والشاشات والمسارات أعلاه. **ما اتجرّبش على أجهزة حقيقية:** الميزان، الطابعات الحرارية، قارئ الباركود الفعلي، كاميرا الموبايل، بوابات الدخول، التحكم بالكهرباء. جرّبها عندك قبل الاعتماد عليها في التشغيل.
